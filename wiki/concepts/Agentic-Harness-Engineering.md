# AHE：可观测性驱动的编码智能体 Harness 自动进化

Agentic Harness Engineering（AHE）是复旦大学与上海启迹智峰（Qiji Zhifeng）联合提出的框架：在基础模型冻结的前提下，由一个进化智能体（Evolve Agent）持续改写编码智能体的整套 [[Harness-Engineering|Harness]]——系统提示、工具、中间件、技能、长期记忆——而非只优化提示词。其核心主张是：Harness 自动进化的瓶颈不在智能体能力，而在**可观测性**（observability）。只要进化智能体能在清晰的动作空间上读到结构化证据，它就能稳定收敛到更优的 Harness 设计。

> **核心结果**：在 Terminal-Bench 2 上运行十轮 AHE 迭代，pass@1 从 69.7% 升至 **77.0%**，超过人工设计的 Codex-CLI（71.9%）与自进化基线 ACE（68.9%）、TF-GRPO（72.3%），全程约 32 小时。冻结后的 Harness 不经再进化即可迁移：在 SWE-bench-verified 上以比种子少 **12%** 的 token 取得最高总成功率；在三个异构模型家族上带来 **+5.1 至 +10.1 个百分点**的跨家族增益，说明进化沉淀的是通用工程经验而非基准特调。

与 [[AutoHarness|AutoHarness]] 由基础模型在环境闭环中合成约束代码、[[Meta-Harness|Meta-Harness]] 由外环智能体检查完整轨迹不同，AHE 把进化拆成三根「可观测性支柱」，让每一次编辑都成为可被下一轮验证证伪的契约。

---

## 问题与动机

编码智能体的 Harness——中介模型与文件系统、Shell、外部服务交互的系统提示、工具与中间件——显著左右长程任务完成率。当前主流做法是人工巡检轨迹、归纳失败模式、修订组件，但这条人工回路昂贵、难规模化、难以科学研究，已跟不上基础模型能力的演进。

已有自动化方案大多只优化单一组件：提示词或上下文内 playbook（ACE）、轨迹反馈强化（TF-GRPO）等。两条结构性障碍横在前面：

- **轨迹信号难消费**：单次 rollout 动辄数百万 token，长而无结构的轨迹对进化智能体几乎没有可用信号
- **Harness 框架紧耦合**：超出提示词之外的编辑极易出错，跨组件的权衡（Trade-off）对优化器不可见

AHE 对此的回答是：让整套 Harness 作为组合整体可调，同时把人工先验压到最低——方法论由优化器从 rollout 中自行发现，而不是手工预先写死。

## 方法：三根可观测性支柱

AHE 把 Harness 优化建模为由另一个智能体驱动的闭环，设计原则是回路的每个阶段都**可观测**：组件编辑、轨迹检查、决策制定三个阶段各配一根支柱，彼此咬合。

```mermaid
graph TD
    subgraph 支柱一：组件可观测性
        N[NexAU 基座<br/>七类组件显式挂载为文件]
    end
    subgraph 支柱二：经验可观测性
        D[Agent Debugger<br/>分层轨迹证据]
    end
    subgraph 支柱三：决策可观测性
        E[Evolve Agent<br/>变更清单 = 可证伪契约]
    end
    R[每任务 k 次 Rollout] --> C[清洗：去 base64<br/>去重工具返回] --> D
    D --> E
    E -->|文件级编辑 + git commit| N
    N --> R
    E -.->|下一轮：归因校验<br/>预测未兑现则回滚| E
```

### NexAU：可编辑、解耦的 Harness 基座

Harness 实例化在 NexAU 框架上，七类正交组件以显式文件形式挂载在同一工作区的固定位置：**系统提示、工具描述、工具实现、中间件、技能、子智能体配置、长期记忆**。组件间松耦合——加一个中间件无需改系统提示，加一个技能无需动任何工具。

解耦直接兑现组件可观测性：每类失败模式映射到单一组件类别，每次通过率变化定位到单个文件，而非散落在数百行无结构提示词里。每次逻辑编辑对应工作区 git 历史上的一次 commit，天然获得文件级 diff 与回滚粒度。

种子 Harness NexAU₀ 刻意保持极简：仅一个 shell 执行工具，无中间件、无技能、无子智能体。若种子已针对目标基准做过适配，后续每次编辑的归因都会被污染——无法分辨增益来自回路还是种子。极简种子迫使 AHE 添加的每个组件都凭实测 rollout 证明自己。

### Agent Debugger：分层轨迹证据

Harness 缺陷导致的错误散落在数百万 token 的原始消息里。Agent Debugger 把轨迹框定为一个可导航的**文件环境**：每条轨迹消息独立成文件，调试智能体用通用 shell 与脚本工具钻取。同一 query 的轨迹归入同一环境，调试器须给出失败的根因或成功的模式，写入**逐任务分析报告**（含 pass/fail 状态，为 Evolve Agent 提供锚点）；所有报告再聚合为一份**基准级总览**，作为每轮迭代的入口。

除报告外，原始轨迹（原始版与轻清洗版并存）同样以文件形式保留，供智能体核验报告中的论断。全部分层材料支持渐进式披露（progressive disclosure），既省 token 又改善决策质量。

### Evolve Agent：证据驱动、可审计的编辑

Evolve Agent 闭合 AHE 回路：每轮读取分层证据语料，决定增、改、删哪些 Harness 组件，落盘到工作区，并记录每次编辑的理由。两条约束共同兑现决策可观测性：

1. **可控性**：Evolve Agent 只能写 Harness 工作区；运行目录、tracer、验证器、LLM 配置均为只读，种子系统提示标记为不可删除。这些限制堵死无约束自我修改者的捷径——禁用验证器、偷换模型、调高推理预算——保证每笔增益都可归因于 Harness 编辑。
2. **可证伪性**：每次编辑附带一条变更清单（change manifest）条目，载明失败证据、推断根因、目标修复手段，以及包含「预期修复」与「回归风险」的预测影响。下一轮把预测集合与实测任务级增量求交，给出逐编辑裁决；未兑现的编辑按文件粒度回滚。每条编辑由此成为一份**可证伪契约**，以轮间可测的契约取代理由驱动的自我辩护。

### 外循环算法

每轮迭代按六阶段推进：rollout → 清洗 → **归因上一轮清单并回滚被拒编辑** → 分层蒸馏 → 工作区编辑并写新清单 → git 打标签提交。每任务跑 k≥2 次 rollout，使每个任务携带通过率信号，稳定 pass@1 并让部分通过的任务支撑对比诊断。归因安排在蒸馏**之前**，其裁决随之进入证据语料，把上一轮清单条目绑定为契约而非说辞。另有一个一次性探索智能体与第 1 轮并行运行，从 NexAU 源码与公开编码智能体资料中播种少量可复用技能；这些技能不受特殊保护，从第 2 轮起可被 Evolve Agent 保留、细化或移除。

## 实验

### 设置

- **进化基准**：Terminal-Bench 2 全部 89 个任务（官方难度划分：4 easy / 55 medium / 30 hard），单任务超时放宽至 1 小时；每任务每轮 k=2 次 rollout
- **迁移基准**：SWE-bench-verified，500 个任务、横跨 7 个仓库
- **指标**：pass@1（基础设施异常或超时计为失败，与官方榜单口径一致）；tokens/trial（千 token 计）；成本效率以 Succ/Mtok（每百万 token 的预期成功数）合并两轴
- **模型**：进化回路与主实验中，Code Agent、Agent Debugger、Evolve Agent 三个角色共享同一基础模型 GPT-5.4（high 推理档），把增益隔离到 Harness 编辑而非分析器或编辑器能力；跨模型迁移另测 GPT-5.4 medium/xhigh、qwen-3.6-plus、gemini-3.1-flash-lite-preview、deepseek-v4-flash
- **基础设施**：Harbor 调度与判分，每次 rollout 跑在全新 E2B 远程沙箱中，InMemoryTracer 记录轨迹并镜像至 Langfuse；Agent Debugger 并发 16、单任务超时 600 秒

### RQ1：主结果（Terminal-Bench 2，pass@1）

十轮迭代、约 32 小时完成单次 AHE 战役，取历史最优配置：

| 方法 | 全部 89 | Easy 4 | Medium 55 | Hard 30 |
|---|---|---|---|---|
| opencode（人工） | 47.2% | 75.0% | 52.7% | 33.3% |
| terminus-2（人工） | 62.9% | 75.0% | 74.5% | 40.0% |
| Codex（人工） | 71.9% | 75.0% | 80.0% | 56.7% |
| NexAU₀（种子） | 69.7% | 87.5% | 78.2% | 51.7% |
| ACE（自进化） | 68.9% | 91.7% | 78.2% | 48.9% |
| TF-GRPO（自进化） | 72.3% | 100.0% | 79.4% | 55.6% |
| **AHE** | **77.0%** | **100.0%** | **88.2%** | 53.3% |

唯一的例外是 Hard 档：AHE 以 53.3% 略逊于 Codex 的 56.7%。作者将其归因于长程任务上组件间的相互干扰而非能力缺失——仅把 AHE 的长期记忆单独换入种子，Hard 档即达 63.3%，反超 Codex（见组件消融）。

对 ACE 与 TF-GRPO 的领先源于**层级错配**：ACE 蒸馏自然语言 playbook 供模型在上下文内阅读，TF-GRPO 强化成功工具序列，两者都不开放外围脚手架的编辑；而 AHE 的增益恰好住在它们从不编辑的组件里（工具 +3.3 pp、中间件 +2.2 pp、长期记忆 +5.6 pp）。

### RQ2：跨基准迁移（SWE-bench-verified）

冻结的 AHE 工作区原样指向新基准，不做域内再进化：

| 仓库 | N | ACE | TF-GRPO | NexAU₀ | **AHE** | AHE tokens k |
|---|---|---|---|---|---|---|
| **全部** | 500 | 74.6% | 74.2% | 75.2% | **75.6%** | **461** |
| django | 231 | 79.2% | 78.8% | 79.2% | **81.0%** | 484 |
| sympy | 75 | 69.3% | 68.0% | 70.7% | 70.7% | 479 |
| sphinx-doc | 44 | 61.4% | 65.9% | 68.2% | **70.5%** | 656 |
| matplotlib | 34 | 70.6% | 70.6% | 73.5% | 73.5% | 391 |
| scikit-learn | 32 | 93.8% | 93.8% | 93.8% | 87.5% | 257 |
| pydata | 22 | 77.3% | 77.3% | 77.3% | 72.7% | 338 |
| astropy | 22 | 59.1% | 59.1% | 54.5% | 50.0% | 277 |

三点读法：

- **提示词系基线出域即退化**：ACE 与 TF-GRPO 总成功率双双跌破未动的种子，token 消耗反而高 11%–29%——playbook 与强化的轨迹分布在 terminal-bench 轨迹上蒸馏，随每次模型调用搭车，换了任务面只剩成本
- **AHE 增益集中在大仓库**：django 与 sphinx-doc 是最大、最耗 token 的两个仓库，其多步「编辑-验证」回路结构与 AHE 组件压缩的模式吻合；边际回退只出现在三个最小仓库，与小样本 pass@1 方差一致
- **成本全面下降**：AHE 聚合 token 较 ACE 省 32%、较 TF-GRPO 省 21%、较种子省 12%。把行为编码进工具、中间件与 [[Memory-Systems|记忆]]，而非塞进提示词，省掉了提示词系方案每次调用的重推导成本。成本效率（Succ/Mtok，越高越好）：AHE **1.64** vs 种子 1.43、TF-GRPO 1.27、ACE 1.10

### RQ2：跨模型迁移（Terminal-Bench 2）

同一冻结工作区换挂五个备选基座，全部为正增益：

| 基座模型 | NexAU₀ | AHE | Δ pass@1 |
|---|---|---|---|
| deepseek-v4-flash | 51.7% | 61.8% | **+10.1 pp** |
| qwen-3.6-plus | 56.2% | 62.5% | **+6.3 pp** |
| gemini-3.1-flash-lite-preview | 36.5% | 41.6% | **+5.1 pp** |
| GPT-5.4 medium | — | — | +2.3 pp |
| GPT-5.4 xhigh | — | — | +2.3 pp |

跨家族增益压过家族内增益：离饱和更远的基座更依赖 AHE 固化在工具、中间件与长期记忆中的协作模式，而强基座能以低边际成本从提示词中重新推导同样的协作。家族内呈非单调（medium +2.3、high +7.3、xhigh +2.3）：AHE 的步数预算与单任务超时是在 GPT-5.4 high 上拟合的，medium 丢一档推理能力，xhigh 把更多 trial 推过超时线（pass@1 口径计为失败）——两个方向都折损增益。作者把超时-预算耦合列为泛化隐患。

### RQ3a：组件消融——增益住在哪里

每行把进化完成的单个组件单独换入 NexAU₀ 种子，其余三类保持种子默认：

| 变体 | 全部 | Easy | Medium | Hard | Δ（全部） |
|---|---|---|---|---|---|
| NexAU₀ | 69.7% | 87.5% | 78.2% | 51.7% | — |
| + 长期记忆 | 75.3% | 50.0% | 83.6% | **63.3%** | **+5.6 pp** |
| + 工具 | 73.0% | 75.0% | 87.3% | 46.7% | +3.3 pp |
| + 中间件 | 71.9% | 100.0% | 81.8% | 50.0% | +2.2 pp |
| + 系统提示 | 67.4% | 75.0% | 78.2% | 46.7% | **−2.3 pp** |
| AHE 完整 | **77.0%** | 100.0% | **88.2%** | 53.3% | +7.3 pp |

两个结构性发现：

- **每个组件分管不同的失败面**：记忆沉淀 12 条边界情形教训（性能裕度、超限排队取消、评测器式闭环、源码打包布局），在 Hard 档甚至超过完整 AHE；工具进化为 1364 行的 shell，自动从命令邻近文件中浮现契约提示，在 Medium 档距完整 AHE 仅 0.9 pp；中间件加 finish-hook 强制一次与评测器同构的闭环检查，Easy 档全清；系统提示的 79 行通用纪律可执行性依赖其余三者，单独插入反而 −2.3 pp
- **组件交互非可加，封顶聚合增益**：三个正增益单组件相加 +11.1 pp，完整 AHE 只得 +7.3 pp。记忆、中间件与系统提示都推向同一种闭环式验证，叠加后在长程预算内互相重复检查；进化智能体优化的是 55 个 Medium 任务主导的聚合指标，收敛到偏 Medium 的权衡，回吐了部分 Hard 档的记忆效应。交互感知的进化留作未来工作

### RQ3b：自我归因的可靠性

每轮变更清单声明「预期修复」与「回归风险」任务集，与下一轮实测对比，9 轮评估的跨迭代均值：

| 预测类型 | Precision | Recall | 随机基线 P / R | 倍数 |
|---|---|---|---|---|
| 修复（fix） | 33.7% | 51.4% | 6.5% / 10.6% | 约 5 倍 |
| 回归（regression） | 11.8% | 11.1% | 5.6% / 5.4% | 约 2 倍 |

修复侧证明进化智能体的瞄准是证据驱动而非猜测；回归侧则是「回归盲」：9 轮中共发出 43 条回归预测，仅 5 条命中（累计 P=11.6%），而实际发生 40 次未预见的回归（累计 R=11.1%）。智能体能论证一次编辑为何有效，却无法可靠点名同一编辑即将破坏哪些任务——这正是进化曲线出现非单调台阶的原因，也是自进化回路最明确的改进方向。

## 案例研究：四轮关键迭代

附录追踪了 best-so-far 曲线上四个峰值对应的八次变更，横跨提示、工具实现、中间件三个可控层级：

| 迭代 | 变更 | 机制 | 效果 |
|---|---|---|---|
| 2 | 68 行提示追加（8 条规则）+ shell 超时参数化 | 契约优先、镜像评测器、防过拟合等规则 | db-wal-recovery 由 1/2 翻为 2/2，此后每轮保持 |
| 5 | publish-state 机制（提示规则 + shell 守卫） | 记录通过验收的文件路径为受保护状态，删除/重置即拦截；override token 可降级为警告并强制重验 | path-tracing 由 0/2 翻为 2/2；拦截「自检通过后 rm -rf 清理掉交付物」的失败模式 |
| 6 | 守卫扩展到脚本入口点 + ExecutionRiskHintsMiddleware | 中间件监视实时命令序列，识别七类跨步风险模式（浅验证、仅 localhost 验证、自写校验顶替命名评测器等） | mcmc-sampling-stan 连挂五轮后翻为 2/2，收敛值 alpha≈2.872、beta≈16.43 落在期望区间中心 |
| 8 | 软拦截升级为硬阻断 + FRAMEWORK 提醒 | 非 /tmp 受保护交付物的删除与根重置改为硬阻断；风险警告在下一模型轮次前提升为推理上下文可见的提醒 | configure-git-webserver、git-multibranch 等翻正；单轮得分 76.97，全程最大跳升 |

值得注意的细节：第 7 轮时得分曾从 75.8 回落至 73.0，Evolve Agent 没有回滚既有组件，而是回头修补守卫的 token 漏洞与中间件的显著性缺口——硬阻断与 FRAMEWORK 提醒正是补丁，最终双双成为关键承载。chg-1 的 68 行提示不含任何 SQLite、WAL 字样，也未把 db-wal-recovery 列入 predicted_fixes，却凭通用表述完成了迁移，展示 AHE 如何把单任务症状转化为可复用的 Harness 规则。

## 局限

- **评估集中于 Terminal-Bench**：单一基准上的增益不能自动外推到其他编码环境、编程语言或部署场景
- **基准特调风险**：多组件可编辑扩大了适配面，也扩大了对基准过拟合的机会；迁移实验是正面测量手段，但负面结果仍可能出现
- **护栏栈不完整**：虽有有界编辑、归因与回滚，长程 Harness 清理与更强的防滥用机制尚未就位，应视为受控研究原型
- **工程与算力开销**：每轮迭代都要跑基准执行、轨迹分析与工作区管理，成本高于一次性提示或人工编辑
- **超时-预算耦合**：进化拟合的步数与超时预算会随基座推理档位变化而折损增益，属泛化隐患

## 讨论：Harness 作为可学习的适配面

AHE 的方法论价值超出分数本身：若 Harness 编辑可积累、可检查、可跨任务迁移，编码智能体就能把经验[[Externalization-in-LLM-Agents|外部化]]为显式工件，而不必依赖隐藏的参数更新——这让测试时学习更可审计、更易科学复现，与 [[From-Weights-to-Context-to-Harness|从权重到上下文再到 Harness]] 的演进脉络一脉相承。组件消融给出的分工图景（事实性结构可迁移，散文级策略不可迁移）也为 [[Harness-Continual-Learning|Harness 持续学习]] 提供了实证支点：长期记忆、工具与中间件是跨任务沉淀经验的载体，而提示词更像是与具体运行点绑定的临时调参。

与 [[Self-Harness|Self-Harness]] 的自我改进思路相比，AHE 的特色在于把「自我归因」本身当作一阶公民来测量：修复预测 5 倍于随机基线、回归预测仅 2 倍的不对称，精确刻画了当前自进化回路的能力边界。

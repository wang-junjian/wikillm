# Harness 能承担多少重担：自我修正智能体能力来源的经验分解

论文原题为 *How Much LLM Does a Self-Revising Agent Actually Need?*——"一个自我修正的智能体到底需要多少 LLM？"。它针对一个被工程实践掩盖的基础科学问题：当世界建模、规划与反思全部塞进同一个 LLM 循环里时，**智能体的能力究竟有多少来自 LLM 本身，又有多少来自围绕它的显式结构（即 [[What-Is-an-AI-Agent-Harness|Harness]]）**？作者不追求普遍答案，而是给出一个让问题可以被经验研究的方法论：把智能体状态、置信信号、守卫动作与假设转移外化为可检查的**声明式反思运行时协议**，再逐层分解测量。

> **核心论点**：外部化反思能把原本潜伏的智能体行为变成可检查的运行时结构，从而让 LLM 干预的边际角色可以被直接测量。结论不是排行榜数字，而是一条设计原则：**能声明的就声明，能符号化反思的就符号化，把 LLM 留给声明式基座解决不了的残差。**

---

## 问题与动机

ReAct、Reflexion 等主流范式（参见 [[Agent-Protocols|智能体协议]]）把推理、工具调用、自我反思都耦合在 LLM 内部，Prompt、隐式推理与外部控制逻辑纠缠在一起，无法回答"哪部分能力来自哪一层"。本文的策略是把纠缠拆开：在一个声明式运行时里，用同一评估 Harness 构造四个逐级增加结构的智能体，让信念追踪、世界模型规划、符号反思、稀疏 LLM 修正各自成为可测量、可消融的独立层。

三个递进的研究问题：

- **RQ1**：把世界结构与提问策略显式声明出来后，带来多少性能增益？
- **RQ2**：智能体能否在局内（in-episode）以纯符号方式、不调用 LLM 地完成自我修正？
- **RQ3**：世界建模与反思都外化之后，稀疏 LLM 干预还剩下多少边际收益？

---

## 方法设计

### 声明式反思运行时协议

协议由四个要素构成：

1. **显式状态**：世界状态、预测记录、误差追踪、策略参数；
2. **计算的置信信号**：模型置信度、修正资格、动作偏好——全部由状态确定性推导，而非 LLM 生成；
3. **守卫动作**：带 `available when` 前提条件的动作，修正动作由"持续低置信 + 正的修正预览"双门控放行；
4. **假设转移**：`sim.next(snapshot, action)` 用于提交前评估候选动作。

主循环为五步：用 `sim.next()` 给候选打分 → 记录预测结果 → 执行并观测 → 用观测对账预测以更新置信度 → 置信度跌够低时应用策略修正。作者明确承认"预测—比较—修正"循环本身历史悠久（OODA、自由能原理），贡献在于把它变成声明式运行时里**显式且可检查**的结构。

核心伪代码展示了反思如何成为"声明的合法性结构"而非 Prompt 模式：

```text
computed modelConfidence = 1 - (predictionErrorEMA + calibrationErrorEMA) / 2
computed confident       = modelConfidence >= confidenceThreshold
computed needRevision    = not confident
computed canRevise       = needRevision and (cooldownRemaining = 0)
computed sustained       = lowConfidenceStreak >= 2
computed revisionRequested = canRevise and sustained
                             and positivePreview and (revisionKind != "")
computed shouldRevise    = revisionEnabled and revisionRequested

action applyRevision available when shouldRevise:
    patch policyParameters <- nextParameters
    patch cooldown <- cooldownTurns
```

置信度、修正资格、修正本身都是可计算、可检查、由守卫动作强制执行的运行时量。基础世界模型（WMA 使用）只含预测追踪，不声明持续置信门、修正预览与守卫修正动作——两个模型之差即**元认知层**。

### 运行时实例化与智能体家族

运行时用一种非图灵完备的 DSL 表达世界模型（声明式状态、计算信号、守卫动作、假设转移）——它是 [[Harness-Runtime-Substrate|运行时基座]] 思路的声明式实例。在此之上构造四个逐级结构化的智能体：

```mermaid
flowchart LR
    G["greedy+MCMC<br/>500 粒子后验<br/>只打最高概率格<br/>不提问、不修正"] --> W["WMA<br/>+ 声明式世界模型规划<br/>sim.next() 评估射击与提问<br/>粗/局部/后期提问预算"]
    W --> M["MRA<br/>+ 预测—比较—修正循环<br/>三个符号修正预设<br/>（零 LLM 调用）"]
    M --> ML["MRA-LLM<br/>+ 置信门打开时<br/>委派本地 9B LLM 修正<br/>LLM 率是阈值的因变量"]
```

三个符号修正预设：`coarse_roi_collapse`（粗粒度兴趣区坍缩）、`late_diffuse_reprobe`（后期扩散重探）、`cluster_closeout_bias`（簇收尾偏置）。MRA-LLM 的关键设计：LLM 调用率不是固定超参数，而是置信阈值的**因变量**——阈值决定门多久开一次。

## 实验结果

**设置**：带噪声的协作海战棋（Collaborative Battleship）：8×8 棋盘、14 个船格、40 发炮弹、15 次提问、观测噪声 ε=0.1；信念用 500 粒子 MCMC 追踪。结果基于 18 个棋盘 × 3 个种子 = 54 局。注意评估使用合成棋盘套件而非 Grand et al. 原基准的发布配置，因此与原文数字（GPT-5 + LIPS + QMD：F1 0.764、胜率 82%）只作方向性参考。

### RQ1：显式世界模型的贡献

| 系统 | 平均 F1 | 胜局 | 胜率 | 平均提问数 | LLM 率 |
|------|---------|------|------|-----------|--------|
| greedy+MCMC | 0.522 | 27/54 | 50.0% | 0.0 | 0% |
| WMA | 0.539 | 40/54 | 74.1% | 11.9 | 0% |
| Δ | +0.017 | +13 | **+24.1pp** | +11.9 | — |

两者共享同一个 MCMC 信念后端，增益完全归因于声明式世界模型规划与提问策略。F1 小涨而胜率大涨的非对称性揭示提问的"最后一公里"功能：由 `sim.next()` 评估的提问规划把边缘局转化为胜局，而不必显著改变整体瞄准精度。针对"基线不提问所以弱"的质疑，作者强调选哪个问题、何时问本身就由声明式规划基座评估与预算约束——增益不是"仅仅问了问题"，而是"在对的时机问对的问题"。

### RQ2：符号自我修正存在，但需要校准

| 系统 | 平均 F1 | 胜局 | 胜率 |
|------|---------|------|------|
| MRA 修正关 | 0.552 | 31/54 | 57.4% |
| 修正开 | 0.551 | 30/54 | 55.6% |
| Δ | -0.001 | -1 | -1.8pp |

聚合上修正开关基本持平甚至略负，作者因此**不主张**当前修正规则集平均有效。证据所示的是：符号反思作为真实运行时机制存在，其有效性取决于校准。分棋盘看：修正有帮助的恢复局包括 B02（+0.140 F1、胜场 1→3）、B14（+0.099）、B17（+0.092）、B09（+0.076）；过度修正的伤害局包括 B01（-0.148）、B15（-0.085）、B11（-0.079）。

**案例 B17-seed0**：修正开启时 MRA 获胜（F1 0.609）——第 2 回合触发 `coarse_roi_collapse`，第 12、15 回合触发 `cluster_closeout_bias`；修正关闭时失败（F1 0.333，40 发炮弹耗尽未完工）。机制在该局是决定性的，即便预设尚未全局校准。方法论要点正在于此：聚合消融的"打平"说明的是预设需要校准，而非机制不存在——把反思变成显式运行时操作才使得这种针对性诊断成为可能。

### RQ3：还需要多少 LLM

| 系统 | 平均 F1 | 胜局 | 胜率 | 平均提问数 | LLM 率 |
|------|---------|------|------|-----------|--------|
| greedy+MCMC | 0.522 | 27/54 | 50.0% | 0.0 | 0% |
| WMA | 0.539 | 40/54 | 74.1% | 11.9 | 0% |
| MRA 修正关 | 0.552 | 31/54 | 57.4% | 8.0 | 0% |
| MRA 修正开 | 0.551 | 30/54 | 55.6% | 8.0 | 0% |
| MRA-LLM 阈值 0.0 | 0.552 | 31/54 | 57.4% | 8.0 | 0% |
| MRA-LLM 阈值 1.0 | **0.557** | 29/54 | 53.7% | 8.9 | 4.3% |

阈值 0.0 时置信门永不打开，系统退化为 MRA 修正关；阈值 1.0 时实测 4.3% 的回合调用了 LLM（54 局共 101 个回合）。阈值 1.0 拿到最高平均 F1（0.557），胜率却是 MRA 变体中最低（53.7%）——LLM 修正似乎改善了局部瞄准质量，同时干扰了局级完成度。F1 与胜率背离的解释：LLM 修正占用的一些回合，若用于策略性时机的提问可能更有价值（WMA 用约 12 次提问拿到 74.1% 胜率，MRA 变体只用约 8 次）。

阈值扫描的附录数据显示明确的非单调性：

| 规模 | 阈值 | LLM 率 | 平均 F1 | 胜率 |
|------|------|--------|---------|------|
| 18 局 | 0.0 | 0.0% | 0.522 | 50.0% |
| 18 局 | 0.5 | 0.0% | 0.522 | 50.0% |
| 18 局 | 0.72 | 1.1% | 0.515 | 50.0% |
| 18 局 | 1.0 | 4.6% | 0.569 | 61.1% |
| 54 局 | 0.0 | 0.0% | 0.552 | 57.4% |
| 54 局 | 1.0 | 4.3% | 0.557 | 53.7% |

阈值 0.0 与 0.5 坍缩进"无 LLM 盆地"；阈值 1.0 在 18 局样本里拿到最好的 F1 与胜率，到 54 局规模时格局部分反转。一旦反思循环显式化，LLM 既不是整个智能体，也不是均匀有益的——它是一种**稀疏修正资源**，其贡献有界、可测、且在此评估设置中非单调。

## 讨论与局限

**分解即方法论**：本文的首要贡献不是某个性能数字，而是让四层能力分别可见的分解——greedy+MCMC 隔离信念，WMA 加声明式规划，MRA 加符号反思，MRA-LLM 加稀疏 LLM 修正。每层的贡献都可独立测量与消融。

**外部化反思买到了什么**：即便 MRA 未改善聚合分数，预测误差、校准误差、置信度、修正资格与修正结果都成为一等运行时变量，"反思"从不透明的 Prompt 模式变成有可诊断失败模式的机制。这与 [[Externalization-in-LLM-Agents|LLM 智能体中的外部化]] 的主线一致，也和 [[Natural-Language-Agent-Harnesses|NLAH]] 的"把控制逻辑变成可分析对象"诉求同构——区别在于本文把反思外化为**声明式运行时的合法性结构**，而非自然语言文本。就自我修正主题而言，本文是 [[Harness-Engineering-Self-Improvement|Harness 工程自我改进]] 的"反向"版本：不是让 Harness 自动变好，而是先声明清楚再测量 LLM 还剩多少活要干。

**局限**（论文自述）：单一领域（协作海战棋，协议原则上领域通用但未在别处检验）；重实现设置（合成棋盘套件 + MCMC 信念，与 Grand et al. 的发布配置只作方向性比较）；统计功效有限（54 局只能揭示定性模式，不支持紧置信区间）；符号修正聚合上非净正（三预设规则集在信念坍缩棋盘上有益、在稳定棋盘上过度修正）；阈值扫描稀疏且结论可能依赖于所用的单一本地 9B 模型。

对 [[Harness-Engineering|Harness 工程]] 领域，本文提供了一面罕见的"反向镜子"：多数工作（如 [[Meta-Harness|Meta-Harness]]、[[HarnessForge|HarnessForge]]）展示 Harness 能贡献多大增益，本文则在四层分解中定量回答"LLM 还必须做多少"——在此设置中，显式规划拿走最清晰的增益（+24.1pp 胜率），符号反思以零 LLM 成本作为机制存在，稀疏 LLM 只剩 4.3% 回合的有界、非单调残差。
